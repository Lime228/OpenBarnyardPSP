# PSP port issue log

This log records reproducible porting failures, their root causes and the check
that closed each issue. Local retail paths and game data are deliberately not
committed.

| Area | Symptom | Root cause | Fix | Verification |
| --- | --- | --- | --- | --- |
| PPSSPP input | Background button injection intermittently failed on 64-bit Windows. | `PostMessage` received a signed pointer-sized value instead of the unsigned virtual-key payload. | Send the key through `UIntPtr` in `RunPPSSPP.ps1` (`bed276a1`). | Analog directions and Circle reached one background PPSSPP instance. |
| PPSSPP runner | A missing PID file made the runner report `not running` and start another PPSSPP while an older port instance was still alive. | Process ownership was tracked only by the disposable PID file. | Discover instances by the exact bundled executable path, adopt the newest managed process and remove managed duplicates before start/input/stop. | Deleting the live PID file now recreates it with PID `5616`; process inventory remains exactly one instance. |
| PWLD build | PSP CI stopped at `python3: not found` before compilation in run `42185795052`. | The intentionally small PSPDEV Docker image has no host Python runtime. | Generate and byte-compare `probe.pwld` on the Ubuntu runner; Premake copies the verified bounded fixture into the target directory (`589137c9`). | PSP run `42186116583` and later runs build successfully; runtime reports `world=OK`. |
| Host build | `PTRB.h` failed when compiled directly by TMDL because `T2StringView` was undeclared. | The header relied on a transitive include. | Include `Toshi/T2String.h` directly (`14e128e6`). | Windows `host-tools` job builds TMDL on VS2022. |
| Local host build | VS2026 linked with `LNK1101 incorrect version MSPDB140.DLL`. | The local MSVC/PDB installation is internally mismatched; source compilation itself completed. | Build the host-only TMDL target in a clean VS2022 GitHub Actions job (`8046f887`) instead of changing game code for a machine-specific toolchain fault. | `OpenBarnyard-PSP-host-tools` is published by every PSP workflow run. |
| TMDL logging | A downloaded TMDL printed `Failed to create file Logs\\...`. | Toshi expects a `Logs` directory relative to the tool working directory. | The retail orchestration creates `TMDL.exe`'s `Logs` directory and executes the exporter with that directory as `cwd`. | Repeated conversions no longer depend on the caller's working directory. |
| Retail skinning | `SS_Sbird2` was rejected at vertex 6 with `bone=6`, even though the model has five bones. | Retail `TTMDWin::Vertex::Bones` stores DX8 matrix registers (`0, 3, 6, 9...`), not palette indices. | Validate register divisibility and export `register / 3` (`1ae85789`). | Model JSON exports 114 vertices; bounded PMES conversion produces 114 vertices and 372 triangle indices. |
| Retail animation | Rotation-only `SS01_GUI_idle` was rejected before sampling. | The exporter required a translation pointer even when the model declares zero translation keys. | Require key arrays only for non-zero ranges and keep a null translation base for rotation-only clips (`bde0f91c`). | The selected idle exports successfully with five bones. |
| Host JSON output | Export created a zero-byte JSON file and returned failure. | An output-only `std::ostringstream` was copied through `rdbuf()`, which sets `failbit` on MSVC without transferring characters. | Write `oOutput.str()` in both PSP exporters (`faf3a924`). | Model and animation JSON files contain 20,100 and 50,228 bytes. |
| Animation budget | A 3-second clip at 30 Hz requires 91 clamp frames, exceeding the 64-frame PSP PANM limit. | Sampling rate was selected without applying the bounded frame count. | Select 20 Hz for this preview (61 frames) and record `sample_rate` in the local manifest. | PANM is 4,912 bytes and reports 61 frames at 20 Hz. |
| Retail texture | The first retail preview could resolve `bird_01` geometry but only displayed `probe.ptex`. | The repository had TTL runtime loaders but no host exporter or PSP-compatible DXT decoder. | Add explicit host-only `TMDL -psp-texture` extraction plus bounded DXT1/3/5 top-mip conversion to swizzled PTEX (`f9648a53`, `ba603658`). | `Char\\SmallBird.tga` extracts from `SS_Sbird2.ttl` as DXT3 64x64; PPSSPP reports `preview_texture=barnyard_preview.ptex` and every gate `OK`. |
| Retail terrain texture | The selected `xroad` mesh exposed only material `lightcone_inner`, so choosing a TTL texture by filename would be guesswork. | Terrain geometry refers to the model TRB `Materials` table; the actual texture is not stored in the mesh record. | Resolve the fixed-size material table during `-psp-terrain` export and carry the exact name through the converter (`3ac8e448`). | `xroad_L0Mod2.trb` resolves deterministically to `World\\nightlight.tga`; the one-step script finds it in `ss01_Common.ttl` and emits a 4,120-byte PTEX. |
| Retail terrain transform | Raw terrain vertices are near `(69,-57,2)` and disappear when drawn with the probe's origin-centred camera. | Static world meshes preserve retail world-space coordinates, unlike the centred preview fixture. | Add a model-space centre/scale transform to the PSP static draw path and keep scene placement separate (`fd2d5438`). | Report v7 records `terrain=ACTIVE`, scale `0.642447` and centre `(69.584244,-56.813332,2.086575)` with every bootstrap gate `OK`. |
| Multi-mesh terrain | Independently auto-fitting `lightcone_inner` and `lightcone_outer` would overlap them and destroy their retail placement. | Per-mesh bounds are unsuitable as scene transforms for meshes belonging to one world cell. | Export the bounded cell as one contract, compute union bounds offline/runtime and apply one transform to all meshes (`4c231429`, `90dcf60c`). | Report v8 records two active meshes with common scale `0.519161` and centre `(69.627716,-57.872467,2.086575)`. |
| Repeated terrain texture | Both light-cone materials resolve to `World\\nightlight.tga`, causing the first cell script to extract and decode the same DDS twice. | Texture ownership is per material, but the source asset is shared. | Cache converted textures by case-insensitive retail name and copy the bounded PTEX for subsequent bindings (`5e187b8d`). | Both 4,120-byte PTEX files have the same SHA-256 while TMDL performs only one successful extraction. |
| PSP package | Earlier builds appeared in tools and PPSSPP as `OpenBarnyard PSP Probe` and had no XMB artwork. | The bootstrap `PARAM.SFO` and PBP optional slots still used development defaults. | Package `ICON0.PNG` (144x80) and `PIC1.PNG` (480x272), rename the module/title, and validate dimensions and file budgets (`d9bc802a`). | PBP section hashes match the source PNGs and the embedded SFO contains `OpenBarnyard PSP`; run `42186116583` is green. |
| Retail frontend DDS | The original Barnyard title assets were rejected with DDS FourCC `0`. | Unlike the DXT preview textures, these retail atlases use masked 16-bit `A1R5G5B5` pixels. | Decode bounded 16/32-bit DDS channels from their explicit masks and pitch before PSP swizzling (`5e721f53`). | The converter test verifies alpha/red/green expansion and the real `barnyard_logo.tga` produces a valid PTEX. |
| Retail title selection | The first six discovered `bkg_E3_TITLE16` tiles formed a screen reading `Thanks for playing / Coming July 2006`. | The container is a genuine retail file but contains a prerelease E3 end card, not the shipping attract screen. | Visually inspect extracted candidate groups, exclude the E3 tiles and use the shipping `Dialogs\\barnyard_logo.tga` referenced by `main.gui` (`f10db9d5`). | The frontend script now publishes only the verified original logo and no prerelease title files. |
| PSP frontend texture | PPSSPP wrote report v9 with `frontend=ORIGINAL_LOGO` and then exited on the first attract-screen frame. | The shipping 512x128 RGBA atlas sat on the PSP GU's maximum texture width and consumed 262,144 bytes for one logo. | Add a deterministic 2x2 box reducer and cap the frontend conversion at 256x64 (`72e6c5b7`). | The 65,560-byte PTEX stays active in PID `8504`; report v9 keeps every gate `OK`, main render memory is 119,632 bytes and background Start leaves PPSSPP alive. |
| Original source compile gate | Including the real game PCH produced missing `TMath`, `TFourCC`, `T2Allocator`, alignment and forwarding symbols. | The PSP PCH had been reduced for the diagnostic harness and no longer provided the vocabulary assumed by original game sources. | Restore the portable `Toshi/Toshi.h` PCH surface, make the allocator headers self-contained and use Toshi memory types (`f16aee45`, `8b63bea9`). | PSP run `42350643321` compiled the complete original game header gate successfully. |
| Retail class layouts | Original controller/loader headers failed exact `sizeof` assertions on PSP even though Allegrex is also 32-bit. | The assertions document MSVC Win32 class ABI and padding, not portable gameplay invariants. | Add `TSTATICASSERT_SIZE`, strict on PC and explicitly skipped on PSP, while keeping ordinary `TSTATICASSERT` active; add a repeatable marking tool (`1fbfbf96`, `4cd89369`). | PSP runs `42351272371` and `42352292418` compile the original state controller and game loader with logical assertions still enabled. |
| Frontend physics dependency | Pulling `AGameLoader` transitively included Opcode, which uses `__declspec`, `__int64` and x86 inline assembly. | The bundled Opcode release is a Windows/x86 backend and cannot execute on Allegrex. | Define the original collision-model interface as `ACollisionModel_PSP` and keep Opcode out of the PSP frontend compile path (`51237197`). | PSP run `42352292418` compiles the full original `AGameLoader.cpp` without any Opcode/x86 dependency. |
| Boot movie dependency | Compiling `ARootTask` required proprietary `bink.h` through `ABINKMoviePlayer`. | The PC boot task instantiated the Windows Bink player directly instead of a platform movie implementation. | Select `AMoviePlayer_PSP` on PSP and reserve offline conversion plus a bounded PSP decoder for the media implementation (`1d2e6790`). | PSP run `42352555138` compiles the original `ARootTask.cpp` without the Bink SDK. |
| Original executable CVar gate | The first `OpenBarnyardPSPGame` target stopped in `AVarType.cpp` because `BOOL` was unknown to PSP GCC. | A file-local initialisation flag leaked the Win32 boolean type into otherwise portable CVar code. | Use the existing `TBOOL`, `TTRUE` and `TFALSE` engine vocabulary for the flag. | PSP run `42409087939` isolated the first executable-gate failure; the following run compiles past the CVar source. |

When a new recurring failure is found, add it here only after the root cause is
confirmed. Include the validation signal (test, CI run or PSP report), not just
the attempted change.
